# YouTube Downloader Pro — نسخة Windows

برنامج سطح مكتب بواجهة عربية داكنة لتحميل الفيديوهات وقوائم التشغيل، وتنزيل الصوت بصيغة MP3. المشروع مجهّز لبناء ملف تثبيت Windows بصيغة `Setup.exe` باستخدام معالج التثبيت التقليدي (Next → Install → Finish)، وللنشر مع قناة تحديثات تلقائية.

## المزايا

- تنزيل فيديو منفرد أو قائمة تشغيل كاملة عبر `yt-dlp`.
- اختيار 2160p/4K أو 1440p أو 1080p أو 720p أو 480p أو 360p أو أفضل جودة متاحة.
- استخراج MP3 باستخدام أفضل مصدر صوت متاح.
- تنزيل ترجمات العربية والإنجليزية، مع خيار تضمينها داخل الفيديو.
- تنزيل/تضمين الصورة المصغّرة وإضافة البيانات الوصفية.
- تنزيل عدة فيديوهات بالتوازي، مع حالة كل عنصر والسرعة والوقت المتبقي.
- اختيار مجلد الحفظ، وإنشاؤه تلقائيًا، وفتح المجلد من الواجهة.
- حفظ تفضيلات المستخدم في `%APPDATA%\YouTubeDownloaderPro`، بحيث لا تُحذف إعداداتك عند تحديث البرنامج.
- التحقق من إصدار البرنامج ومكتبة `yt-dlp` عند التشغيل، وتقديم تحديث البرنامج من خلال مُثبّت Windows عند توفر إصدار أحدث.
- تنزيل FFmpeg/ffprobe وDeno إلى مجلد المستخدم عند أول تشغيل، ثم فحص إصداراتهما وتحديثهما تلقائيًا عند توفر تحديث.
- تثبيت مستوى المستخدم دون الحاجة إلى صلاحيات Administrator.

## ما الذي يحتاجه الكمبيوتر الذي سيبني المثبّت؟

يحتاج جهاز البناء إلى Windows 10/11 واتصال بالإنترنت، وPython 3.11 أو أحدث، وInno Setup. **أجهزة المستخدمين الذين يثبتون `Setup.exe` لا تحتاج إلى تثبيت Python أو pip أو FFmpeg يدويًا.** في أول تشغيل يحتاج البرنامج إلى الإنترنت لتنزيل FFmpeg وDeno، لأنهما يُنزّلان مباشرة من مصادرهما بدل تضمين ملفاتهما التنفيذية داخل المثبّت.

### تثبيت الأدوات على جهاز البناء

1. ثبّت Python 3.12 من الموقع الرسمي، مع تفعيل خيار **Add Python to PATH**.
2. ثبّت Inno Setup من الموقع الرسمي، أو من PowerShell:

   ```powershell
   winget install --id JRSoftware.InnoSetup -e
   ```

3. فك ضغط المشروع في مجلد عادي، مثل `C:\Projects\youtube-downloader-pro`.
4. انقر مرتين على `build_windows.bat`.
5. سيُنشئ الملف بيئة بناء مستقلة، ويثبت `yt-dlp[default]` وPyInstaller، ثم يبني التطبيق ويُنشئ المثبّت.
6. ستجد الناتج هنا:

   ```text
   Output\YouTubeDownloader-Setup.exe
   ```

المثبّت الناتج يعمل من خلال معالج تثبيت بخطوات **Next / Install / Finish**، ويضيف اختصارًا لقائمة Start وخيارًا اختياريًا لسطح المكتب.

## تفعيل التحديثات التلقائية للبرنامج نفسه

التحديث التلقائي يحتاج إلى مكان تُنشر عليه الإصدارات الجديدة. إعداد GitHub Actions في هذا المشروع يقوم بهذا العمل، لكن يجب إعداد مستودعك مرة واحدة لأنني لا أملك مستودع نشر خاصًا بهذا المشروع.

1. أنشئ مستودع GitHub **عامًا** جديدًا.
2. ارفع ملفات المشروع كلها إلى الفرع الافتراضي. لا ترفع مجلدات `.venv` أو `build` أو `dist` أو `Output`؛ فهي مستثناة داخل `.gitignore`.
3. من إعدادات المستودع افتح **Settings → Actions → General → Workflow permissions**، واسمح للـ workflow بالقراءة والكتابة إلى المستودع.
4. افتح تبويب **Actions**، ثم شغّل workflow باسم **Refresh yt-dlp and publish Windows installer** باستخدام **Run workflow**. خيار `force_release` مفعّل افتراضيًا.
5. شغّل الـ workflow مرة واحدة من **Actions → Refresh yt-dlp and publish Windows installer → Run workflow**. سيكتشف إصدار `yt-dlp` الحالي، ويرفع رقم إصدار البرنامج، ويبني `YouTubeDownloader-Setup.exe` على Windows، وينشره ضمن **GitHub Releases** مع ملف SHA-256 للتحقق.
6. نزّل ملف المثبّت من أول Release وثبّته. إذا نُشر تحديث لاحق، فسيتحقق البرنامج منه عند التشغيل ويعرض عليك تنزيل المثبّت الجديد.

بعد ذلك يعمل الفحص تلقائيًا مرة يوميًا. عندما يصدر تحديث جديد لمكتبة `yt-dlp` أو أداة بناء PyInstaller، ينشئ الـ workflow نسخة جديدة من البرنامج وينشر المثبّت. كما أن تغييرات ملفات المشروع التي تُرفع إلى `main` أو `master` تبدأ بناء إصدار جديد تلقائيًا. أما تحديثات FFmpeg وDeno فتُفحص وتُنزّل مباشرة داخل البرنامج عند تشغيله، دون الحاجة إلى إعادة تثبيت التطبيق.

> استخدم مستودعًا عامًا إذا أردت أن يستطيع التطبيق فحص إصدارات GitHub وتنزيلها من دون بيانات دخول. لا تضع أي أسرار أو رموز وصول داخل ملفات المشروع.

## التثبيت اليدوي للمكتبات (للتطوير فقط)

إذا أردت تشغيل الواجهة من Python بدل بناء المثبّت:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-build.txt
python yt_playlist_downloader.py
```

في وضع التطوير، تُحدّث ميزة التحديث مكتبة `yt-dlp` داخل بيئة Python الحالية عند الموافقة. في نسخة Windows المثبتة، تُحدَّث المكتبة من خلال إصدار تطبيق جديد.

## الملفات الأساسية

- `yt_playlist_downloader.py` — واجهة البرنامج ومنطق التنزيل.
- `runtime_tools.py` — تجهيز وتحديث FFmpeg/ffprobe وDeno على جهاز المستخدم.
- `requirements.txt` — إصدار مكتبة `yt-dlp` الذي سيُستخدم في بناء الإصدار المنشور.
- `requirements-build.txt` — مكتبات بناء نسخة Windows.
- `installer.iss` — تعريف معالج التثبيت Inno Setup.
- `scripts/build_windows.py` — بناء التطبيق وملف Setup.
- `scripts/check_upstream.py` — فحص إصدار yt-dlp وتجهيز إصدار جديد عند الحاجة.
- `.github/workflows/refresh-and-release.yml` — التحديث اليومي والنشر الآلي.
- `build_config.json` — قناة تحديثات البرنامج، ويُضبط المستودع تلقائيًا أثناء النشر.
- `THIRD_PARTY_NOTICES.md` — روابط تراخيص الأدوات الخارجية.

## ملاحظات مهمة

- أنشئ المثبّت على Windows؛ PyInstaller ليس أداة لبناء تطبيق Windows من Linux. انظر [التوثيق الرسمي لـ PyInstaller](https://pyinstaller.org/en/stable/).
- يجب أن يكون الإنترنت متاحًا عند أول تشغيل لتجهيز الأدوات، وكذلك عند البحث عن تحديثات أو تنزيل محتوى.
- لا يمكن تثبيت تحديث جديد أثناء استخدام ملفات التطبيق؛ عند تحديث البرنامج، سيطلب منك مثبّت Windows إغلاق النسخة الحالية عند الضرورة.
- التنزيلات تخضع لشروط YouTube والقوانين المعمول بها. نزّل فقط المحتوى الذي تملك حق تنزيله أو لديك إذن بذلك.


## حل مشكلة ظهور كلمات عربية كأوامر في نافذة CMD

إذا ظهرت رسائل مثل `is not recognized as an internal or external command` مع أجزاء عربية أو كلمات مثل `xe` و`aller`، فغالبًا أن نسخة ملف Batch القديمة لم تُقرأ بترميز مناسب في Windows. استخدم نسخة `build_windows.bat` الموجودة في هذا الأرشيف؛ تم جعلها ASCII فقط لتجنب مشكلة الترميز، مع تفعيل UTF-8 لرسائل Python. لا تحتاج إلى تعديل الكود يدويًا.
